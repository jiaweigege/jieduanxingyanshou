# Spec Delta

## Purpose

提供可重复的一键接口验收工程，按 HTTP 路径和方法定位测试脚本，核对接口内容与数据库状态，并输出便于检查的本地 HTML 报告。

## ADDED Requirements

### Requirement: 接口测试按 URL 和方法组织
仓库 MUST 包含 `apitest/cases/`，每个被测接口使用独立脚本，目录对应 URL 路径、文件名对应 HTTP 方法；例如 `cases/api/auth/token/POST.py` 对应 `POST /api/auth/token`。测试可共享准备数据和断言工具，但不能将不同接口合并到一个案例脚本。

#### Scenario: 定位接口测试
- **WHEN** 开发者需要检查某接口的测试
- **THEN** 可依据 URL 目录和方法文件名直接找到该接口的脚本

### Requirement: 一键运行并生成可忽略报告
`apitest/run_all.py` MUST 能用明确的本地配置一次执行所有案例，汇总通过、失败及原因，生成 HTML 报告并以进程退出码表示整体结果。报告和运行期数据 MUST 不提交到 Git。

#### Scenario: 全部通过
- **WHEN** 开发者运行 `run_all.py` 且服务符合合同
- **THEN** 所有案例执行完毕、报告列出每个结果，进程退出码为零

#### Scenario: 案例失败
- **WHEN** 某接口响应或数据库状态不符合断言
- **THEN** 运行器继续汇总其他案例，在报告中记录失败原因并以非零码退出

### Requirement: 校验响应内容和数据库一致性
案例 MUST 不只判断状态码，还要检查必要字段、错误码、班级隔离、来源及流式事件；涉及持久化的案例 MUST 对照隔离测试数据库验证写入、归属和读取结果。至少 MUST 覆盖登录、检索、技能/提示词、创建会话和发送一条消息。测试 MUST 使用可控的模型替身或注入传输，不依赖真实个人密钥或实时外部模型。

#### Scenario: 成功会话流
- **WHEN** 接口测试创建学生会话并发送消息
- **THEN** 案例核对事件顺序、引导内容、引用及数据库中的学生消息和成功助手消息

#### Scenario: 跨班访问
- **WHEN** 案例以 A 班身份请求 B 班资源和不存在资源
- **THEN** 案例核对两者状态、错误结构一致，并确认数据库未产生越权写入
