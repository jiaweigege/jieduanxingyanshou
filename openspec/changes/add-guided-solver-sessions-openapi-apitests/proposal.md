# Proposal

## Why

当前系统只支持基于本班知识库的单次、非流式问答，教师无法管理“只引导、不直接给答案”的解题规则，学生也没有可持续的会话和流式体验。同时，现有 API 缺少可在浏览器试调的 OpenAPI/Swagger 合同和独立的端到端接口回归套件，难以稳定验收课程要求。

## What Changes

- 增加班级范围的“解题引导”技能配置：教师可创建、查看和更新至少一条提示词，系统强制它仅提供思路、提问和分步引导，不直接给出最终答案。
- 增加学生解题会话：学生创建会话后发送一条消息，服务端先检索本班知识库，再以流式事件返回引导内容和可核验引用。
- 延续现有 Bearer Token 鉴权、服务端用户班级判定和“跨班资源与不存在资源表现一致”的防枚举语义。
- 提供覆盖主要接口路径、请求/响应、错误码和安全要求的 OpenAPI 描述，以及浏览器可访问、可填写 Bearer Token 试调的 Swagger UI。
- 新建 `apitest/`独立接口测试工程，按 URL/方法组织一接口一脚本，由 `run_all.py` 一键执行并生成不纳入 Git 的 HTML 报告。
- 接口测试除状态码外，校验 JSON/流式事件内容、引用和数据库持久化，至少覆盖登录、检索、提示词/技能、创建会话并发送一条消息。

## Capabilities

### New Capabilities

- `guided-solver`: 定义教师管理班级解题引导技能、学生会话、检索先行的流式回答、引用与班级隔离。
- `api-documentation`: 定义 OpenAPI 合同和可在浏览器中认证、试调主要接口的 Swagger UI。
- `api-contract-testing`: 定义按 URL 组织的接口测试、响应与数据库一致性断言、一键运行和 HTML 报告。

### Modified Capabilities

无。当前项目没有已归档的主规格。现有未归档规格将作为相关背景；其中跨班资料详情的 403 要按本次要求调整为与不存在资源一致的 404，并同步修订受影响的旧规格与测试。

## Impact

- 数据层：新增班级技能/提示词、会话、消息及引用关联数据，并为所有持久化资源保留班级和用户所有权。
- API 层：新增技能管理、会话创建与消息流接口；现有登录、检索、资料和单次问答合同被纳入 OpenAPI。
- 模型调用：复用现有本班检索与智谱集成，将非流式上游请求扩展为可验证的流式传输，并合并教师配置的解题引导约束。
- 前端/文档：新增会话与逐段回答界面、Swagger UI 入口及 OpenAPI JSON/YAML 资源。
- 测试与依赖：新增 `apitest/` 运行器和 HTML 报告产物忽略规则；如实施需引入任何非官方来源下载，必须在下载前说明来源和用途并取得用户同意。
