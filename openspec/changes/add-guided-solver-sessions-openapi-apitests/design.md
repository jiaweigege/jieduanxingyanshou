# Design

## Context

项目是 Flask + SQLAlchemy + SQLite FTS5 单体应用。现有 `/api/auth/token` 签发 Bearer Token；`/api/knowledge/search` 在服务端按用户班级检索；`/api/knowledge/answer` 使用用户临时智谱密钥进行非流式单轮问答。资料详情和文件目前对跨班 ID 返回 403，对不存在 ID 返回 404，这与本次防枚举要求冲突。浏览器目前用 `sessionStorage` 保存应用访问令牌，个人模型密钥仅在当前页面内存中。

## Goals / Non-Goals

**Goals:**

- 复用现有鉴权、检索与来源结构，新增持久化学生会话和真正逐段到达的回答流。
- 让教师可管理本班提示词，同时由服务端固定的高优先级规则维持“只引导”约束。
- 将可执行接口合同与独立接口验收工程纳入仓库。

**Non-Goals:**

- 不引入跨班共享、跨班教师管理或模型密钥托管。
- 不将旧单次问答迁移为多轮会话，也不替换现有检索索引。
- 不保证模型在所有题型中绝不会说出答案；通过提示词分层、完成前校验和测试降低风险，检测到直接答案时失败关闭。

## Decisions

### 1. 资源与接口

选择 `/api/solver/skills`（GET、POST）、`/api/solver/skills/{id}`（GET、PATCH）、`/api/solver/sessions`（GET、POST）、`/api/solver/sessions/{id}`（GET）和 `/api/solver/sessions/{id}/messages`（POST）。写技能仅教师；建会话和发送消息仅学生。POST 消息 JSON 包含 `content` 和个人临时 `api_key`。不接受客户端班级或作者作为授权依据。用户自己班级和本人范围内查询；资源未命中统一返回 JSON `{"error":"not_found"}`、404。旧资料详情/文件也按此语义调整。相比建立平行的登录或检索 API，这组路径直接复用现有协议。

### 2. 数据模型与初始化

新增 Skill（班级、名称、提示词、启用标记、版本）、SolverSession（班级、学生、技能、创建时间）及 SolverMessage（会话、角色、正文、来源 JSON/关联记录、创建时间）。数据库外键和服务端查询共同限制归属；每班初始化一条默认技能，可重复执行且不覆盖教师修改。技能更新只影响之后生成的消息，成功消息保存当次技能版本。上线时只增表/索引，已有资料、令牌、单次问答数据不迁移。选择持久化会话而非页面内存，是为了重读、来源核对和数据库断言。

### 3. 检索、生成和流式协议

复用 `retrieve_answer_sources` 的班级过滤及编号来源。输入校验、所有权检查、检索在响应开始前完成；无命中不调用模型。上游使用智谱的官方流式响应格式，服务端解析并将安全文本片段转为 `text/event-stream`：`sources`（来源数组）、若干 `delta`（有序文本片段）、`done`（消息 ID、引用编号、generated），或 `error`（稳定错误码）。请求使用 fetch + ReadableStream，因 EventSource 不适合带 Bearer 的 POST。设置 `Cache-Control: no-store`、`X-Accel-Buffering: no`，并关闭反向代理缓冲；每个事件及时 flush。Swagger 合同附带事件示例，Try it out 至少展示原始流。

服务端系统规则优先于教师提示词，检索文本以明确边界标记为不可信。上游片段先经增量解析，再在缓冲窗口内检查泄漏密钥、越界引用及明显的最终答案模式；只有确认可发送的片段才下发。已下发内容无法撤回，因此发现违规时以 `error` 终止且不写成功助手消息，前端将该流标记失败、隐藏或清除部分回答。成功终止前校验全文引用与来源，并在同一事务中保存问题和助手消息，随后发送 `done`。客户端断线时不写成功助手消息。此策略比直接转发上游字节更适合强制引导与引用约束。

### 4. 安全与失败语义

应用 Bearer Token 只从 Authorization 头读取；模型密钥只用于本请求上游 Authorization，绝不持久化。没有令牌返回 401；学生写技能或教师创建学生会话返回 403；跨班/他人/不存在的资源统一 404。流开始前错误使用普通 JSON 与相应 HTTP 码；流开始后使用 `error` 事件，随后结束连接，不发送 `done`。明确区分 `invalid_message`、`invalid_api_key`、`retrieval_unavailable`、`provider_auth_failed`、`ai_unavailable`。已有单次问答 JSON 合同保持原样。

### 5. OpenAPI、Swagger 与接口验收

将 OpenAPI 3.1 文档作为仓库内单一版本化文件，由公开 `/openapi.json` 提供；`/docs` 提供 Swagger UI。UI 静态资源须随应用部署；优先选官方发布包并锁定版本，不从运行时 CDN 拉取。新增依赖若来自非官方来源，实施前先告知用户来源及用途并等待同意。

`apitest/cases/api/.../{METHOD}.py` 各自暴露统一案例入口，`run_all.py` 发现并执行脚本。共享 fixture 启动隔离的测试应用/SQLite 库、种子用户和可控模型流；通过 Flask 测试客户端调用真实路由，故无须真实智谱密钥或独立服务进程。持久化接口同时查询数据库核对记录和归属；报告用标准库 HTML 转义生成，写入 `apitest/reports/`，并在 `.gitignore` 忽略。此方案比依赖外部测试服务器更可重复，也能直接检查数据库。

## Risks / Trade-offs

- 流式回答中的违规文本一旦发出便不可收回 → 增量缓冲校验，违规时终止流，前端清除部分结果，且测试覆盖已开始后的失败。
- Flask/WSGI 或代理缓冲可能让用户看不到逐段输出 → 使用流式生成器和禁缓冲头，并用延迟模型替身测试首段在完成前到达；部署文档注明代理配置。
- 模型可在不同题型中绕开“不给最终答案”的简单模式 → 固定高优先级规则、保守校验、失败关闭，并建立具体题型回归样例；不宣称数学语义上绝对可靠。
- 403 改 404 会改变现有资料接口合同 → 同步更新既有未归档规格、旧测试及 OpenAPI，明确为本次要求的兼容调整。
- 官方 Swagger UI 资源可能需要新增依赖 → 优先复用仓库或官方包；任何非官方来源下载先征得用户同意。

## Migration Plan

1. 添加新表和索引，幂等创建每班默认技能；保留现有数据与端点。
2. 发布新路由和文档，调整跨班资料访问为 404，更新旧测试与相关未归档规格。
3. 接入前端流式界面和独立接口套件，在隔离数据库上验证完整链路。
4. 回滚时停止使用新路由和界面；新增表可保留以避免数据丢失，既有单次问答继续可用。
