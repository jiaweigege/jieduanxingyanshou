# Spec Delta

## Purpose

定义登录用户所在班级范围内的安全知识正文检索行为，并要求每条结果包含足够的来源信息，使用户能够对照受保护的原始资料核验命中片段。

## ADDED Requirements

### Requirement: 知识检索必须经过身份认证
系统 MUST 允许已登录的教师和学生检索知识内容，并 MUST 对未登录的检索请求返回 HTTP 401，且不得返回任何知识内容或来源元数据。

#### Scenario: 已登录的班级成员检索知识
- **WHEN** 已登录的教师或学生提交有效的知识检索词
- **THEN** 系统只在该用户获授权的班级范围内处理查询

#### Scenario: 未登录用户检索知识
- **WHEN** 未登录的客户端调用知识检索接口
- **THEN** 系统返回 HTTP 401，且不返回结果正文或来源元数据

### Requirement: 检索范围受登录用户班级限制
系统 MUST 根据登录用户在服务端保存的身份确定检索班级。系统 MUST NOT 使用客户端提交的班级标识扩大或替换该边界，并且 MUST 只返回班级与登录用户一致的内容分块。

#### Scenario: 同班正文匹配
- **WHEN** A 班用户检索同时存在于 A 班和 B 班知识内容中的文字
- **THEN** 返回的每条结果都属于 A 班，且不返回任何 B 班内容或元数据

#### Scenario: 客户端提交其他班级
- **WHEN** A 班用户通过查询参数、请求正文、请求头或其他字段提交 B 班标识
- **THEN** 系统仍然只检索 A 班，且不返回任何 B 班内容或元数据

#### Scenario: 查询只匹配其他班级
- **WHEN** A 班用户的查询只匹配 B 班的知识内容
- **THEN** 系统返回 HTTP 200 和空结果列表

### Requirement: 检索查询具有稳定的校验和空结果行为
系统 MUST 对缺失、空字符串或只包含空白字符的查询返回 HTTP 400。有效查询在授权范围内没有匹配内容时，系统 MUST 返回 HTTP 200 和空结果列表。

#### Scenario: 空白查询
- **WHEN** 已登录用户提交缺失、为空或只包含空白字符的查询
- **THEN** 系统返回 HTTP 400、稳定的错误码，且不返回结果

#### Scenario: 授权范围内无匹配
- **WHEN** 已登录用户提交有效查询，但其班级内没有匹配内容
- **THEN** 系统返回 HTTP 200 和空结果列表

### Requirement: 检索结果包含相关片段和可验证来源
每条检索结果 MUST 包含与查询相关的内容片段、来源资料标题和标识、稳定的分块标识、来源起止行号，以及受保护的资料详情和原始文件链接。结果 MUST 按检索相关性排序，并使用确定性的次级排序规则。

#### Scenario: 返回实际命中片段
- **WHEN** 查询命中授权资料中远离正文开头的位置
- **THEN** 结果包含命中位置附近的片段，而不是无关的固定开头摘要

#### Scenario: 结果标明来源
- **WHEN** 系统返回一条知识检索结果
- **THEN** 结果包含来源资料标题、资料标识、分块标识、起始行、结束行、详情链接和文件链接

#### Scenario: 同分结果顺序稳定
- **WHEN** 多条授权结果具有相同的相关性分数
- **THEN** 系统应用确定性的次级排序，使数据不变时重复查询得到相同顺序

### Requirement: 访问来源时重新检查身份和班级权限
用户访问来源详情或文件链接时，系统 MUST 独立执行身份认证和班级权限检查。用户 MUST NOT 通过获取或修改结果链接访问其他班级的内容或元数据。

#### Scenario: 访问已授权来源详情
- **WHEN** 已登录用户打开其所在班级资料的结果详情链接
- **THEN** 系统返回受保护的资料详情

#### Scenario: 访问已授权来源文件
- **WHEN** 已登录用户打开其所在班级资料的结果文件链接
- **THEN** 系统返回该资料的原始文件

#### Scenario: 使用跨班来源标识
- **WHEN** A 班用户请求属于 B 班资料的详情或文件链接
- **THEN** 系统与不存在的资料一样返回 HTTP 404，且不泄露 B 班正文、文件名、标题或其他来源元数据

### Requirement: 成功上传的资料可检索且不存在部分索引状态
教师成功上传资料后，系统 MUST 创建与该资料及教师班级关联的可检索分块。如果分块创建或索引持久化失败，系统 MUST NOT 将上传报告为成功，也 MUST NOT 留下看似有效但无法参与检索的资料。

#### Scenario: 上传正文可被检索
- **WHEN** 教师成功上传受支持的文本资料，且同班成员检索该资料正文中的内容
- **THEN** 系统返回引用该上传资料的检索结果

#### Scenario: 上传过程中索引失败
- **WHEN** 上传处理期间发生分块创建或检索索引持久化失败
- **THEN** 系统报告上传失败，且本次尝试不留下已提交的资料、知识条目、分块、索引记录或上传文件

### Requirement: 已有知识条目可以回填索引
系统 SHALL 提供可重复执行的管理操作，为已有知识条目创建或刷新可检索分块和索引记录，同时保留其资料和班级归属。

#### Scenario: 回填已有条目
- **WHEN** 管理员对已有知识条目执行回填操作
- **THEN** 每个有效条目都获得可检索分块，且分块保留相同的资料和班级归属

#### Scenario: 重复执行回填
- **WHEN** 管理员在来源内容没有变化时再次执行回填操作
- **THEN** 生成的分块和索引记录保持等价，且不会重复

### Requirement: 检索索引故障必须明确返回
当检索索引不可用、缺失或无法正常使用时，检索接口 MUST 返回 HTTP 503 和稳定的错误码，并且 MUST NOT 静默扩大检索范围、跨越班级边界，或将不完整结果作为成功检索返回。

#### Scenario: 检索索引不可用
- **WHEN** 已登录用户提交有效查询，但检索索引无法提供服务
- **THEN** 系统返回 HTTP 503、稳定的检索不可用错误码，且不返回任何结果
