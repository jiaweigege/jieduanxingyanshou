# Proposal

## Why

当前项目只有固定的知识问答和解题引导流程，缺少可配置的 AI 应用、模板、Skill 与 MCP 工具平台能力。同时，现有实现无法系统证明每次 LLM 调用究竟携带了哪些模板、知识片段、Skill 指令和工具定义，也无法安全核对模型返回内容与工具执行链路。

## What Changes

- 增加多 AI 应用目录，每个应用可独立绑定模型配置、提示词模板、知识库、Skill 和外部工具。
- 增加带变量声明、渲染校验和版本快照的提示词模板，并明确渲染后内容会作为消息传给 LLM。
- 将现有班级知识检索扩展为应用可绑定的知识库上下文：每次仅传递限量、相关且授权的片段，不传递整库全文。
- 建立内置 Skill 目录与可上传 Skill 包的校验、版本、启用和执行机制；常规对话只向 LLM 提供 Skill 索引/摘要，选中或执行时才按需加载必要指令。
- 增加外部工具和 MCP 服务器接入，通过允许列表、参数 schema 校验、超时和结果限额控制模型工具调用循环。
- 增加结构化 LLM 调用跟踪，记录实际出站请求参数、模板/Skill/知识/工具来源、有界脱敏原始响应、解析结果和工具循环。
- 增加自动化验证，覆盖普通对话、模板渲染、知识检索、Skill 加载/执行及 MCP 工具调用时的实际出站请求和返回处理。

## Capabilities

### New Capabilities

- `ai-application-catalog`: 多 AI 应用的定义、配置组合、发布与对话入口。
- `prompt-template-rendering`: 提示词模板的变量、渲染、版本快照及 LLM 消息组装规则。
- `knowledge-context-assembly`: 知识库绑定、权限内检索、片段限额和上下文注入规则。
- `skill-package-runtime`: 内置与上传 Skill 的包格式、验证、加载、选择和受控执行语义。
- `mcp-tool-integration`: 外部工具/MCP 的注册、暴露、调用循环、结果回填和失败边界。
- `llm-call-tracing`: 可验证且脱敏的 LLM 请求、响应、知识、Skill 与工具调用跟踪。

### Modified Capabilities

无。当前主规范库为空；现有行为仅存在于未归档变更与实现中，本变更以新能力规范承载平台行为。

## Impact

- 后端：需扩展 Flask 路由、持久化模型、对话编排、知识检索、提供商客户端和审计记录。
- 前端：需增加应用目录/配置、模板管理、Skill 上传、MCP 连接和授权后调试跟踪界面。
- API：需增加应用、模板、知识库绑定、Skill 包、工具连接、对话与跟踪端点，并更新 OpenAPI 契约。
- 安全与运维：需引入包大小/文件类型限制、MCP 连接凭据管理、出站地址策略、调用超时/限额和跟踪数据保留/脱敏策略。
- 测试：扩展单元、API 和端到端契约测试，使五项调用透明性问题可以通过确定性 transport 替身验证，不向外部服务发送真实数据。
