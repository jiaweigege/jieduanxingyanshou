# Design

## Context

动机见 proposal.md。已只读检查 Flask 路由、SQLAlchemy 模型、检索与智谱传输、浏览器解题逻辑以及相邻测试，得到以下实施基线：

| 位置 | 已观察到的行为 | 对本设计的约束 |
| --- | --- | --- |
| `app/qa.py` | `ZhipuClient.generate` 发送 model、messages、stream=false、temperature=0.1、max_tokens；解析 `choices[0].message.content`，移除 think 文本并校验引用 | 在最终 HTTP transport 处取证，分别记录提供商内容与用户可见答案 |
| `app/solver.py`、`app/solver_stream.py` | 每轮把完整 `skill.prompt` 放在 user 消息；system 固定引导规则；stream=true；逐事件读取 `choices[0].delta.content` | 当前 Skill 是提示词记录，并非可上传的技能包；保留旧语义，新平台另设按需加载机制 |
| `app/qa.py`、`app/retrieval.py` | 本班过滤、FTS5 与词项排序、去重；最多 4 个来源、默认正文预算 6000 字符 | 扩展资料集合过滤时必须在候选查询和排名之前限制到绑定知识库，不能先跨库取 Top-K 再过滤 |
| `app/models.py` | teacher/student 角色、class_id、会话所有权、复合外键约束；没有应用、模板、Skill 包、MCP 或追踪模型 | 沿用班级作为已有隔离域，不在此次引入个人账号或新租户体系 |
| `app/routes.py`、`app/static/js/solver.js` | 学生拥有解题会话；保存成功问答，但模型只收到当前问题、Skill 和来源，历史不重放 | 新平台初版沿用“保存历史供查看、每条消息独立组装”的模式；不隐式假定已有多轮上下文 |
| `tests/test_qa.py`、`tests/test_solver.py` | 已有注入 transport、密钥哨兵、跨班、流失败测试 | 用真实序列化边界和替身 transport 建立确定性验证，无需真实 Key |

`openspec list --specs --json` 返回空清单。既有需求仍在未归档变更中：`add-guided-solver-sessions-openapi-apitests` 约定旧解题流程完整使用教师提示；`add-zhipu-knowledge-qa` 与检索变更约定临时个人 Key、仅本班来源与无命中不调用。这些约束和新平台的渐进 Skill 加载并存，通过新增平台端点隔离，禁止静默替换原流程。README 对多轮历史的描述与当前“可保存解题历史”的实现不完全一致，更新时应准确说明“存储记录”和“发送历史”两个概念。

## Goals / Non-Goals

**Goals:**

- 将应用配置、上下文组装、工具调度和出站取证接在同一条可测试的执行链上。
- 以现有班级、角色和个人临时模型 Key 为基础，提供可展示的个人项目平台；新增平台的教师和学生均可拥有自己的应用会话。
- 提供通用对话、知识问答、解题引导三个内置应用，以及解题引导、资料摘要两个内置 Skill。
- 对五个验证问题给出可读请求、响应、加载文件与调用顺序的证据，且明确证据的脱敏和截断范围。

**Non-Goals:**

- 初版不提供任意脚本/命令执行、容器沙箱、上传程序安装、插件市场自动下载、多模态模型输入、MCP prompts/resources 全量导入或 stdio 子进程管理。
- 本次不替换 FTS5 为向量数据库，不改变账户体系和现有学生专属解题入口，不引入 LLM Key 持久化或自动重试。
- 不承诺只靠提示词就能严格保证回答质量；保留来源、输出格式和现有引导校验，验证报告区分参数正确性与生成内容质量。

## Decisions

### 1. 增量添加平台配置和运行模型

继续使用 Flask、SQLAlchemy、SQLite 与原有静态脚本方式；新增模块按应用管理、上下文、技能包、工具和追踪分离，路由通过服务层调用。相较前后端重写或引入独立 Agent 服务，这能直接复用认证、检索和测试替身。

新增逻辑实体：

| 实体 | 关键字段与关联 |
| --- | --- |
| AiApplication / ApplicationVersion | class_id、slug、用途、草稿/已发布版本、模型标识、能力要求、生成与执行预算、模板版本及绑定快照 |
| PromptTemplate / TemplateVersion | class_id、正文、变量声明、不可变版本和摘要 |
| KnowledgeBase / KnowledgeBaseMaterial | class_id、名称、资料集合，约束资料与库属于同班 |
| SkillPackage / SkillVersion / SkillFile | class_id、builtin/upload 来源、名称/说明、内容摘要、不可变文本及规范化路径 |
| ToolConnection / ToolDefinitionVersion | class_id、http/mcp 类型、HTTPS 目标、凭据引用、启用状态、协议版本、审核 schema 摘要 |
| AppConversation / AppMessage | class_id、owner_id、application_id、消息内容、消息状态；与旧 SolverSession 分离 |
| ConversationRun / LlmCall / RunEvent | 会话及所有者、配置快照、调用序号、来源映射、脱敏请求/响应、工具/Skill 事件、状态、到期时间 |

表内采用班级复合键/外键并在服务层校验，避免只靠前端隐藏。内置内容按班级幂等初始化，保持同一隔离方式。应用发布固定所有版本，运行开始时再次确认资源可用；若执行中资源被禁用，在下一次加载或外部调用前拒绝该操作，不因已固定版本而绕过撤销。

旧表和端点保持原样。使用新增表和幂等初始化替代破坏性迁移；不把旧 `SolverSkill.prompt` 原地转换为包，防止改变旧会话行为。

### 2. 统一编排，但维持两种模型传输模式

新 `ConversationRunner` 顺序处理：认证及所有权检查 → 固定应用版本 → 校验输入/临时 Key → 建立 run → 渲染模板 → 在绑定范围检索 → 准备 Skill 摘要或显式 Skill 正文 → 预算检查 → 调用模型 → 校验及执行内部加载工具/外部工具 → 回填并继续 → 校验最终答案 → 保存结果及结束状态。

初版平台工具循环采用非流式 Chat Completions（`stream=false`），避免在只支持文本 delta 的旧解析器上混合拼接工具参数。无工具应用也使用这一平台响应模式。旧解题入口继续 SSE，追踪适配它的实际事件流；不强迫两个端点共享尚不兼容的解析逻辑。统一的是 transport 取证与上下文元数据，不是把协议差异抹平。

默认一轮最多 6 次模型调用、8 次工具调用，单工具 10 秒、整轮 120 秒；内部 Skill 加载同样计入工具和模型预算。超过上限以 `tool_budget_exceeded` 或 `run_timeout` 结束，未完成内容不可标为成功。每个会话同时只允许一个运行中消息，重复提交使用客户端 request_id 去重，避免浏览器重复发送触发重复外部动作。一次提供商/工具网络调用失败不自动重放。

### 3. 消息组装明确来源、顺序和预算

新平台每轮重新组装，不把上轮检索文本、Skill 正文或工具结果隐式回放。用户可查看已保存的历史，但调用面板明确显示 `history_replayed=false`。后续多轮上下文是独立演进项。

按顺序生成：

1. system：平台固定规则，以及应用类型必须维持的知识来源/解题引导约束。
2. user：以 `<application_template>` 包裹的渲染模板、以 `<skill_catalog>` 包裹的摘要、显式选中的 `<active_skill>` 正文、`<knowledge_source>` 片段及来源编号、当前问题。教师模板和上传文件均属于低于平台规则的内容，分隔标记用于来源识别，不视为安全隔离机制。
3. 工具循环中追加助手 `tool_calls` 与匹配 `tool_call_id` 的 tool 消息。当前轮已加载指令继续保留；不得无条件追加重复文件。

模板仅接受 `{{name}}` 文本变量，使用独立受限渲染器，不以完整 Jinja 执行教师内容。变量值只替换一次。消息来源映射记录角色、messages 索引、字符范围和资源版本，映射到最终提供商请求而非中间对象。

应用发布需要模型 capability 配置，工具应用只接受已声明且经替身/集成契约验证支持 tool_calls 的模型；不假定现有默认 `glm-4-flash` 在任何版本都支持这些能力。不支持的配置发布失败，运行时不静默删掉 tools。优先保持现有智谱 Chat Completions 协议，通过适配器统一参数和响应。

输入预算由部署配置的模型上下文限额、预留输出 tokens 和各资源上限共同约束；没有可靠 tokenizer 时采用保守 UTF-8 字节上界估计并记录 estimated 标志。先去重/减少知识片段和可选参考文件，固定规则、当前问题、已选 Skill 必要正文和 schema 若仍超限则返回 `context_budget_exceeded`，不能静默删去关键指令。

### 4. 知识库复用分块索引，绑定只决定候选范围

新增命名知识库与资料集合，将绑定集合交集同时应用到 FTS 和关系查询，再排名、去重和选取。保持来源链接现有认证方式。现有检索候选上限会影响召回，应在追踪中呈现候选受限信息；本次优先保证范围和注入证据，不声称召回完整。

默认最多 4 个片段、正文合计 6000 字符；模板、来源标题和包装额外计入整体输入预算。若最后一段被裁剪，保留原始分块 ID，同时另记实际发送行/字符范围，避免只显示原分块行号而夸大已发送内容。

知识问答和解题引导无命中则本地返回资料不足，通用对话可继续无资料生成。小库全部相关且落在预算内时，可能恰好全部发送；“检索式注入”不等于承诺任何情况下发送量必小于库大小。

### 5. Skill 采用声明式文本包和渐进加载

初版支持单个 SKILL.md，或根目录 SKILL.md 加 references 下 `.md`/`.txt` 文件的 ZIP。YAML front matter 至少含 name、description；可声明 allowed-tools 作为工具范围的进一步收窄，不能据此增加应用权限。文件总数默认不超过 32，压缩包不超过 2 MiB，解压总量不超过 8 MiB，主正文不超过 16000 字符，单参考文件不超过 64000 字符；限制可部署配置且入库前同时校验。

使用安全 YAML 解析、逐项检查 ZIP 元数据和实际读取字节，不解压到任意用户路径；规范化路径后将校验通过的文本作为版本化文件保存。拒绝链接、路径穿越、规范化重名、嵌套压缩及脚本，不跟随远程链接。与允许任意包内代码执行相比，文本包加注册工具能满足技能指令执行与调用链验证，同时无需新增沙箱运行时。

绑定后默认仅注入名称、description、版本和标识。显式选中时，首个模型请求加载该版本 SKILL.md 正文；自动选择时，模型先看到目录和内部 `load_skill` 工具，平台验证后以 tool 结果回填正文。内部 `read_skill_reference` 只允许读取本轮已加载版本内明确路径并受预算限制。正文可能在执行时被完整发送，但包内未读取的参考文件不会被自动发送；这与当前每轮完整发送 `SolverSkill.prompt` 的旧模式有明确区别。

Skill 执行即“加载任务指令 → 模型据此生成回答或请求工具 → 平台校验并调度 → 模型基于结果继续”。SKILL.md 本身不是程序，绑定也不是执行。状态事件使用 selected/loaded/running/completed/failed；普通应用对话不等于已完成某个 Skill。

### 6. 外部工具统一定义，MCP 使用明确版本的客户端

外部 HTTP 工具由教师登记工具名称、说明、输入/输出 schema、HTTPS 方法/路径和参数映射，不接受上传 Python/JavaScript 适配代码。平台将其转换为与 MCP 工具相同的 ToolDefinition，统一实施授权、参数校验和结果限额。

MCP 初版兼容目标固定为 **2025-11-25**，通过官方 Python SDK 封装 HTTPS Streamable HTTP 生命周期及 JSON/SSE 响应；实现时选定支持该协议、与本项目 Python 运行时兼容的 SDK 发布版并锁定依赖。不以“跟随 latest”作为兼容约定，不支持的协商版本直接报错。协议传输和工具发现/调用依据官方 [Transports](https://modelcontextprotocol.io/specification/2025-11-25/basic/transports) 与 [Tools](https://modelcontextprotocol.io/specification/2025-11-25/server/tools) 规范。具体生命周期和会话字段交由该版本 SDK，平台只提供策略及工具适配。

模型只接收已绑定工具的名称、说明与 JSON schema，以及 tool_choice；平台维护模型可用名称到 connection_id、远端工具名的映射，使用命名空间避免重名。工具清单分页读取，schema 在发布时审核并固定；远端列表变化先失效缓存和相关绑定，再由教师重新确认发布，不能立即让新工具进入模型上下文。

LLM 返回的工具请求不是 MCP 网络报文：平台解析 name/arguments，经权限与 schema 校验后，再向 MCP 发起 tools/call。结果中支持文本和 structuredContent；其他类型只返回“当前不支持”的元信息，不自动抓取链接或把二进制传给文本模型。每次工具结果默认最多回填 16000 字符并记录原始字节数、摘要及截断状态；若有 outputSchema，先校验完整有界结果，再进行面向 LLM 的限量投影。

连接凭据使用部署环境中的凭据引用，数据库和应用 API 不保存或返回明文；普通教师只能选取部署允许本班使用的引用。每个调用从引用解析临时值，仅送往对应连接。目标域名由部署允许列表控制，阻止回环、私网、链路本地和元数据地址；解析与连接阶段均校验，禁止跨域重定向及隐式凭据转发。自有演示服务使用显式允许的 HTTPS 地址；测试用替身不打开网络。工具是否执行由应用已发布的工具集合及当前权限决定，远端 annotations 不构成本地授权。

### 7. 追踪是 transport 边界的有界脱敏证据

追踪分 run、LLM call 和工具/资源事件。LLM call 在最终 URL/headers/body 生成后、网络发送前捕获；同时适配原有非流式和 SSE transport。不存登录请求和个人 Key 请求体，只记录它们如何被剔除以及实际提供商 body。保存实际脱敏序列化 body，并另外保存解析 JSON 以便查看，不能只保存模板的抽象描述。

请求体中核心字段示例（值为示意占位，不是已执行结果）：

```json
{
  "model": "<已配置模型>",
  "messages": [
    {"role": "system", "content": "<平台及应用固定规则>"},
    {"role": "user", "content": "<渲染模板、技能摘要/已选正文、检索片段、问题>"}
  ],
  "stream": false,
  "temperature": 0.1,
  "max_tokens": 512,
  "tools": [{
    "type": "function",
    "function": {
      "name": "kb_lookup",
      "description": "查询已绑定资料",
      "parameters": {"type": "object", "properties": {"query": {"type": "string"}}, "required": ["query"]}
    }
  }],
  "tool_choice": "auto"
}
```

无可用工具时省略 tools/tool_choice；有工具时两者的实际值必须入追踪。认证在 `Authorization: Bearer [REDACTED]` 请求头，而非 messages。记录提供商实际返回的 id、model、choices、finish_reason、usage 等存在字段，不虚构提供商未返回的字段。后续模型请求增加助手 tool_calls 与 tool_call_id 匹配的 tool 结果；MCP 请求参数单独在工具事件中记录。

run 执行中的明文凭据只驻留内存，递归处理结构化秘密字段，并替换已知 LLM Key、登录令牌、MCP 凭据和敏感参数在字符串中的回显；对任意格式原文也适用。SSE 先在有界内存中聚合并处理跨 chunk 的秘密，再持久化脱敏事件，禁止逐 chunk 直接保存导致密钥拼接泄露。请求、响应和工具结果默认分别最多记录 256 KiB，超过限额标记 captured_bytes/total_bytes/truncated；无法确定总长时明确标为 unknown，不能假装完整。原始未脱敏内容不写临时文件，不计算并保存可用于猜测秘密的明文摘要。内容摘要针对已脱敏表示。

调用前无法建立追踪则返回 `trace_unavailable`，不发送无法取证的外部请求；调用后写入失败则将 run 标为异常，不把结果标为已完整取证。追踪错误日志只含 run_id 和错误类型。详细追踪只供会话所有者读取，教师管理配置不获得学生对话权限；默认 7 天保留，查询时立即隐藏过期内容，并由幂等清理命令物理清除到期/所有者删除内容。失败 run 也使用同一权限与过期规则。

### 8. 五项验收矩阵以实际边界数据为依据

| 用户要求 | 当前能确认的事实 | 新平台验收证据 |
| --- | --- | --- |
| 每次 LLM 请求/返回及模板是否发送 | 当前参数见 Context；固定 system 与完整教师 prompt 会随消息发送，尚无可管理模板与追踪面板 | 模板唯一哨兵出现在真实序列化 body，固定 Key 只在 transport 鉴权头，响应原文/解析答案/可见结果可对照 |
| 知识库是否每次全量发送 | 当前选择至多 4 段、正文预算 6000 字符，不发送全库 | 大库中命中、未命中、未绑定、跨班段分别置哨兵；只允许命中且授权且在预算内的片段进入请求；另测小库恰好全命中 |
| Skill 是否每次发送全部内容 | 当前完整发送 prompt，但尚无技能包 | 已绑定未加载只有摘要；显式选中有完整主正文；读取一个参考后只出现该参考，其他文件哨兵不出现 |
| Skill 如何执行 | 当前只把 prompt 加入消息，由模型生成引导，无脚本执行 | 自动/显式选择、加载、读取、工具调用和最终生成的事件按 call_id 关联，可逐步复现 |
| MCP 接入后请求参数是什么 | 当前没有 MCP/tools 参数 | 首次请求含允许 schema 与 tool_choice；响应含 tool_calls；工具事件含 MCP name/arguments/result；下一模型请求含助手调用和匹配 tool 结果 |

验证使用 transport 替身和同一份假数据，不以模型随机文本作为参数正确性的依据。追踪与捕获请求做“仅排除已声明脱敏/截断差异”的深比较；使用假的提供商 JSON/SSE 验证响应解析、usage 缺失、工具参数格式、流中断、工具失败及密钥跨 chunk 回显。真实联调仅在实现后用户自行提供临时 Key 和允许地址时运行，并明确样例与实测状态。

### 9. 页面与 API 围绕可用应用和调用证据组织

新增 `/apps` 目录及应用会话页面，复用当前 token 获取和安全文本渲染。教师界面提供模板、知识库资料选择、Skill 上传、工具连接/发现及应用发布；学生只看到可用应用和自己的历史。消息详情提供“本次调用”面板，展开 request、response、上下文来源与执行事件；原始 JSON 作为转义文本呈现，导出也执行同一脱敏器。

建议 API 分组：`/api/apps` 与版本发布、`/api/prompt-templates`、`/api/knowledge-bases`、`/api/skill-packages`、`/api/tool-connections`（连接测试与发现）、`/api/app-conversations` 及其 messages、`/api/conversation-runs/{run_id}`（详情、导出、删除）。OpenAPI 必须覆盖 400 校验、401、403、404、409 并发/失效配置、422 提供商鉴权和 503 检索/提供商/追踪不可用。平台消息初版返回最终 JSON、run_id、generated、来源和状态，前端可查询所属 run 的事件。

## Risks / Trade-offs

- [绑定和知识来源扩大后出现跨班泄露] → 数据约束、候选查询前过滤、每次引用/加载/调用重验权限，以及跨班/同班他人会话反例测试。
- [上传指令或工具结果诱导越权] → 固定规则、工具能力交集、schema 校验、禁用自动链接抓取；不把来源分隔符当作完整防护。
- [完整追踪复制用户内容并增加存储] → 仅所有者可读、默认 7 天、手动删除、内容限额、到期清理、明确脱敏与截断范围；不把“脱敏”声称为删除所有个人信息。
- [MCP 与模型工具协议差异] → 固定 MCP 兼容版本、官方 SDK、显式模型能力检查与两层协议分开取证。
- [非流式平台调用体验较慢] → 展示执行状态与有限步骤；保留旧解题流式入口，后续再扩展完整工具 delta 解析。
- [进程退出导致外部调用结果未知] → 超时清理遗留 running 状态为 interrupted，禁止自动重放；request_id 复用返回原状态，用户可查看失败证据。
- [旧变更尚未归档] → 不修改其产物，旧端点回归覆盖；以后归档时单独处理主规格合并，当前变更不假定其他变更均已部署。

## Migration Plan

1. 在测试数据库验证新增表、复合约束和幂等平台初始化，备份现有 SQLite 和上传目录；部署开关 `AI_PLATFORM_ENABLED` 默认关闭。
2. 增量创建新表，为每个现有班级建立默认知识库并关联本班资料，创建模板、内置应用与 Skill；默认库新增上传自动关联，手动创建的库使用显式成员管理。
3. 加入新平台 transport 取证和旧端点取证适配，验证原请求/响应不变；所有凭据仅使用部署引用或请求内临时值。
4. 完成离线五项验证、旧接口回归、OpenAPI 与 UI 检查，再打开平台入口。没有配置的外部工具/MCP 不显示为已可用。
5. 提供平台追踪清理和 interrupted run 恢复命令，纳入部署运维；保留期隐藏逻辑不依赖定时任务成功执行。
6. 回滚先关闭平台开关并恢复旧代码入口；新增表/文件保留以便恢复，不删除原数据。必须物理回退数据库时从已验证备份恢复，不做原表破坏性转换。
