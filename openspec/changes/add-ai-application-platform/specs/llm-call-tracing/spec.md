# Spec Delta

## Purpose

为每轮对话提供与实际传输边界一致的请求和响应证据，使用户能够核对模板、知识片段、技能及工具如何进入模型上下文，同时保护请求凭据并明确未记录或截断的部分。

## ADDED Requirements

### Requirement: 每次实际模型调用有独立证据
系统 SHALL 为每条用户消息建立 run_id，并为本轮每次实际 LLM 网络尝试建立 call_id 和顺序号，记录配置版本、提供商/模型、请求时间、耗时、脱敏 URL/请求头和实际序列化请求体、HTTP 状态及有界脱敏响应。请求证据 MUST 在最终参数和序列化均完成的 transport 边界捕获，不能只记录预组装模板。未调用模型的本地结果 SHALL 显示零次调用和原因。

#### Scenario: 请求与传输边界一致
- **WHEN** 确定性 transport 接收请求并返回响应
- **THEN** 除显式脱敏字段外，追踪展示的 JSON 参数与 transport 实际收到的参数相同，并包含对应响应

### Requirement: 返回内容可区分原始与用户可见结果
系统 SHALL 分别展示提供商原始脱敏 JSON/SSE、解析后的文本/工具调用、finish_reason、可用的 usage 和最终用户可见结果。流式调用 SHALL 保留有序事件及完成/中断状态；缺少 usage SHALL 标为未提供。正文超出记录限额 SHALL 标明截断、总字节数和已捕获范围；格式错误或校验失败 SHALL 记录明确原因，且不伪造成功。

#### Scenario: 提供商响应解析失败
- **WHEN** 提供商返回非 JSON、缺失字段或不完整 SSE
- **THEN** 追踪包含有界脱敏原文和解析失败状态，用户收到稳定错误码且没有成功完成记录

### Requirement: 上下文来源和执行链可关联
系统 SHALL 记录模板版本及渲染消息位置、知识片段和发送范围、Skill 摘要/正文/参考文件加载记录、工具定义及 schema 版本、工具调用参数/结果及其前后模型 call_id。界面和导出 SHALL 能分别回答五项验证问题：请求与返回是什么、模板是否发送、知识是否全量发送、Skill 是否全包发送及如何执行、MCP 如何进入模型参数。

#### Scenario: 同轮发生 Skill 和 MCP 调用
- **WHEN** 一轮先加载 Skill，再执行 MCP 工具，最后产生答案
- **THEN** 追踪按顺序显示每次模型输入的增量与完整脱敏请求、加载资源及工具参数/结果，能识别未发送的库内容和技能文件

### Requirement: 追踪不保存凭据且受会话所有权保护
系统 MUST 在持久化、日志输出、展示和导出前对个人 LLM Key、登录令牌、MCP/HTTP 凭据以及已声明的敏感参数递归脱敏，包括它们在模型响应或工具结果中的回显。追踪 MUST 仅由会话所有者读取，教师配置权限 MUST NOT 自动授予学生完整对话读取权限。追踪 SHALL 默认保留 7 天并提供所有者删除功能，响应 SHALL 使用 no-store。

#### Scenario: 敏感值被上游回显
- **WHEN** 提供商或工具在任意嵌套字段及流事件中返回已知密钥哨兵
- **THEN** 数据库、日志、界面、API 响应和导出均不含哨兵原文，脱敏位置有明确占位标记

#### Scenario: 他人访问或过期
- **WHEN** 用户请求他人的 run_id，或请求已删除/过期的追踪
- **THEN** 返回与不存在记录相同的 404，不暴露内容或归属

### Requirement: 五项验证可自动复现
系统 SHALL 提供离线契约测试和可执行的验证步骤，覆盖无绑定、模板、知识库、Skill 绑定/显式执行/按需读取及 MCP 循环。测试 SHALL 在实际 transport 边界断言请求与响应并与脱敏追踪比较，使用独特哨兵证明确有发送和确未发送的内容；默认测试 MUST NOT 访问真实提供商或真实外部工具。

#### Scenario: 执行验证套件
- **WHEN** 在隔离测试数据库运行五项验证
- **THEN** 每项输出通过或失败及对应断言依据，所有请求使用替身传输，能够定位到模板、检索、Skill 或工具循环的具体调用
