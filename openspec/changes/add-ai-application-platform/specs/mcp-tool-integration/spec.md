# Spec Delta

## Purpose

让应用能够使用已注册外部工具以及通过 MCP 发现的工具，明确区分模型收到的工具定义、平台执行的远程调用和下一次模型请求中的工具结果，并提供可核验的调用边界。

## ADDED Requirements

### Requirement: 外部工具和 MCP 连接可配置
教师 SHALL 能登记本班的外部 HTTP 工具以及 HTTPS Streamable HTTP MCP 连接，校验连接状态并选择允许绑定的工具。MCP SHALL 采用明确的协议版本，完成该版本要求的连接生命周期、分页工具发现和调用。工具定义变更 SHALL 使已审核绑定失效，直到重新审核发布；不支持的协议或 schema SHALL 返回明确错误。

#### Scenario: 发现并选择 MCP 工具
- **WHEN** 已配置连接返回多页工具清单且教师只绑定其中一个
- **THEN** 系统完整处理发现结果，但模型只可见该已绑定工具，未绑定项不出现在请求中

### Requirement: LLM 仅接收允许的工具定义
每次可调用工具的模型请求 SHALL 仅附加当前授权且应用绑定的工具名称、说明和参数 schema，以及明确的工具选择策略。MCP 服务地址、连接鉴权字段和服务端实现代码 MUST NOT 被作为工具定义发送给 LLM。MCP JSON-RPC 消息 SHALL 由平台客户端发送，LLM 请求 SHALL 使用模型提供商的工具调用格式。

#### Scenario: 检查首次工具请求参数
- **WHEN** 应用在本轮启用一个 MCP 工具
- **THEN** 出站模型请求含对应 tools 定义和 tool_choice，既不含 MCP 鉴权信息，也不含 MCP tools/list 的完整协议报文

### Requirement: 平台验证和执行工具循环
收到模型工具请求后，系统 MUST 校验工具名称、绑定及用户当前权限、JSON 参数与已固定 schema，只有全部通过才执行。工具返回 SHALL 作为对应 tool_call_id 的工具结果加入下一次模型请求，且 SHALL 保留引发调用的助手消息。多个工具调用 SHALL 各自关联结果。工具结果中的指令 MUST NOT 覆盖平台规则。

#### Scenario: 完成一轮工具调用
- **WHEN** 模型返回合法工具调用，工具返回结果，模型据此回答
- **THEN** 追踪包含首次模型请求/响应、实际工具参数/结果及含助手 tool_calls 和 tool 消息的后续模型请求/响应

#### Scenario: 工具越权或参数不合法
- **WHEN** 模型请求未绑定工具、连接已禁用、未知工具或不满足 schema 的参数
- **THEN** 平台不调用外部服务，记录拒绝，并将稳定错误回填或终止本轮

### Requirement: 工具执行受容量和地址边界约束
系统 MUST 对连接目标实施服务端允许列表与地址校验，对工具执行施加超时、轮数、次数及结果大小限制。达到限额或连接失败 SHALL 返回可识别失败状态，不得无限重试、把失败结果视为成功或自动重放未知结果的调用。初版 SHALL 仅向文本模型回填文本及 JSON 结果，不自动获取工具返回链接指向的内容。

#### Scenario: 超时或耗尽预算
- **WHEN** 工具超时、重复调用达到上限或返回超大结果
- **THEN** 系统记录超时/限额/截断信息，停止相应执行或返回带标记的限量结果，并且不发生无界调用

#### Scenario: 禁止目标或链接诱导
- **WHEN** 用户配置被禁止的地址，或工具结果包含内部网络链接
- **THEN** 系统拒绝禁止的连接，不自动抓取结果链接，且不向其转发用户或服务凭据
